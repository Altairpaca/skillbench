# v0.2 acceptance contract

v0.2 promotes SkillBench from static validation plus relative comparison into a CI decision layer with portable evidence packaging.

## In scope

- deterministic gate policy separated from regression compatibility;
- strict default requirement that the current skill itself conforms;
- configurable warning escalation with explicit allow-listing by check ID;
- strict canonical JSON hashing for structured evidence;
- `skillbench.bundle/v1` with per-entry and whole-bundle SHA-256 integrity;
- malformed-bundle verification that returns structured failure rather than crashing on an invalid payload;
- CLI exit codes suitable for CI gates;
- zero model/API dependency for the deterministic kernel.

## Invariants

1. A current skill that still fails conformance does not pass the default gate merely because the baseline failed in the same way.
2. Gate behavior is fully represented by the emitted normalized policy.
3. Warning exemptions identify stable check IDs, not message text.
4. Bundle hashes are order-stable for semantically identical JSON object key ordering.
5. Canonical evidence accepts only JSON values: null, booleans, finite numbers, strings, arrays and plain objects.
6. Values JSON cannot represent faithfully (`undefined`, non-finite numbers, non-plain objects or cycles) are rejected rather than silently coerced.
7. Mutating a bundled payload without updating its digest fails verification.
8. Verification of malformed entry payloads reports `valid: false` with errors instead of throwing from the integrity checker.
9. SHA-256 integrity is never described as authentication or digital signing.

## Deferred to host evidence

The following remain outside cloud-only acceptance because their truth depends on installed runtimes or filesystem behavior:

- Codex/Claude/OpenCode/DSH execution compatibility;
- host-specific skill discovery and installation paths;
- symlink/copy/update behavior;
- subscription or credential-backed execution.

Those observations can later be carried as named payloads inside the same evidence bundle format.

## Exit codes

- `0`: command completed and its verdict/decision is passing;
- `1`: validation, comparison, gate, or bundle verification completed with a failing result;
- `2`: usage, parsing, I/O, or execution error.
